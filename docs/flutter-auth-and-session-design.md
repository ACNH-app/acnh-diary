# Flutter 인증/세션 설계

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`

## 1. 현재 기준

1. 별도 앱 서버 없음
2. 앱 데이터는 디바이스 로컬 DB에 저장
3. 1차 모바일 앱은 로그인 없이 진행
4. 유료 기능은 광고 제거만 제공

## 2. 1차 앱 정책

1. 로그인 화면 없음
2. 회원가입/계정 연동 없음
3. 인증 토큰 저장 없음
4. 사용자 식별자 발급 없음
5. 결제 상태는 스토어 복구 기능 범위 내에서만 사용

## 3. 필요한 추상화

1. `PremiumState`
2. `PurchaseService`
3. `AdVisibilityPolicy`
4. `LocalProfileStore`

## 4. 왜 인증이 필요 없는가

1. 데이터 저장 위치가 모두 로컬이다.
2. 다른 사용자와 같은 상태 저장소를 공유하지 않는다.
3. 멀티디바이스 동기화가 없다.
4. 유료 여부도 앱 계정이 아니라 스토어 구매 복구 기준으로 처리한다.

## 5. 결제 상태 처리 원칙

1. 광고 제거 entitlement만 가진다.
2. 프리미엄 상태는 `free` 또는 `ad_free` 두 단계만 사용한다.
3. 스토어 복구 성공 시 광고 제거 상태를 다시 활성화한다.
4. 앱 삭제 후 재설치는 스토어 복구 플로우로 대응한다.
5. 앱 자체 계정 인증은 도입하지 않는다.

## 6. 차기 확장 시점

아래 조건이 생기면 그때 인증 도입을 다시 검토한다.

1. 사용자별 백업/복원
2. 여러 기기 간 상태 동기화
3. 서버 기반 이벤트/콘텐츠 배포
4. 유료 사용자별 클라우드 기능 차등 제공

## 7. 현재 결론

현재 설계 범위에서는 인증/세션 계층이 필요 없다. 대신 로컬 사용자 상태 저장과 스토어 구매 복구 흐름만 설계한다.
