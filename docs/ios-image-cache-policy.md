# iOS 이미지 캐시 정책

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`
- 목적: 현재 서버의 이미지 소스 구조를 기준으로 iPhone 앱 이미지 로딩/캐시 정책을 정의한다.

## 1. 현재 이미지 구조

1. 주민/일반 카탈로그 이미지는 API 응답 URL 우선
2. 음악 이미지는 서버 정적 자산(`/static/assets/music/...`) 사용
3. 실패 시 `/static/no-image.svg` 폴백

## 2. 앱 정책

1. 모든 원격 이미지는 메모리 + 디스크 캐시 사용
2. 리스트는 썸네일 우선, 상세는 큰 이미지 우선
3. 이미지 로딩 실패 시 앱 내 placeholder 표시
4. 음악 이미지도 일반 원격 이미지와 동일한 캐시 경로로 처리

## 3. 캐시 구분

### 3.1 메모리 캐시

목적:

1. 최근 화면 재진입 속도 개선

정책:

1. 리스트 썸네일 우선 보관
2. 메모리 압박 시 자동 제거

### 3.2 디스크 캐시

목적:

1. 앱 재실행 시 재다운로드 감소
2. 약한 오프라인 대응

정책:

1. 최대 용량 초기값 `200MB`
2. LRU 기반 정리
3. 오래된 항목 자동 삭제

## 4. 우선 캐시 대상

1. 주민 목록 썸네일
2. 카탈로그 목록 첫 화면 썸네일
3. 최근 본 상세 이미지
4. 홈에서 반복 노출되는 대표 이미지

## 5. fallback 규칙

1. 서버 이미지 URL 없음 -> 앱 placeholder
2. 다운로드 실패 -> 앱 placeholder
3. placeholder도 카테고리별 시각 차이를 둘 수 있지만 1차는 공통 이미지 사용

## 6. 프리페치 정책

1. 목록 스크롤 시 다음 셀 몇 개만 선로딩
2. 상세 진입 직후 인접 아이템까지 무리하게 프리페치하지 않음
3. Wi-Fi 전용 대량 사전 다운로드는 1차에서 제외

## 7. 성능 규칙

1. 목록 셀에서 원본 큰 이미지를 직접 쓰지 않는다.
2. 화면 밖 이미지 작업은 취소 가능해야 한다.
3. 같은 URL 중복 요청을 합친다.

## 8. 차기 개선

1. 이미지 크기별 캐시 분리
2. 음악 자산 사전 다운로드 옵션
3. 저속 네트워크 모드에서 저해상도 우선 전략
