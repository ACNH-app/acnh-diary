# 모바일 앱 전환 현재 상태 진단

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`

## 1. 현재 구조 요약

현재 프로젝트는 `FastAPI + static SPA` 구조다. 정적 데이터 본문은 `content.db`와 로컬 JSON 매핑을 사용하고, 사용자 상태는 `app.db` SQLite에 저장한다.

## 2. 모바일 앱에서 재사용 가능한 것

1. `/api/villagers`, `/api/catalog/*`, `/api/home/*`, `/api/profile`, `/api/players`, `/api/calendar` API
2. `content.db`와 매핑 파일을 기반으로 한 서버 데이터 모델
3. 주민/카탈로그/프로필/일정 상태 개념
4. 이미지 소스 구조와 음악 정적 자산 구조

## 3. 그대로 쓰기 어려운 것

1. 현재 웹 네비게이션과 모달 중심 UX
2. 인증 없는 상태 변경 API 구조
3. 웹 중심 로딩/오류 처리 방식
4. 모바일 오프라인 대응 부재

## 4. Flutter 앱 전환 시 핵심 과제

1. 공통 모바일 정보 구조 설계
2. Flutter 앱 상태관리와 Repository 계층 설계
3. 오프라인 캐시와 제한적 쓰기 큐 설계
4. 공개 배포 전 인증 도입 여부 결정
5. 앱 스토어 제출용 메타/정책 준비
