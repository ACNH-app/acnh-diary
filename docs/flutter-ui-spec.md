# Flutter 화면별 UI 명세

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`
- 플랫폼: `iOS + Android (Flutter)`

## 1. 목적

이 문서는 Flutter 앱의 각 화면에서 필요한 UI 구조, 상태, 액션, 예외 처리를 정의한다.

## 2. 공통 UI 원칙

1. 탭 루트 화면은 스크롤 위치와 필터 상태를 유지한다.
2. 목록 화면은 `로딩`, `정상`, `빈 결과`, `에러` 상태를 모두 가진다.
3. 상세 화면은 fullscreen route를 기본으로 하고 편집은 바텀시트 또는 다이얼로그를 사용한다.
4. 파괴적 액션은 항상 확인 다이얼로그를 거친다.
5. 상태 변경 직후 셀 단위 피드백을 우선 보여주고 전체 화면 새로고침은 지연 적용한다.

## 4. 홈 화면

### 4.1 목표

오늘 확인해야 할 정보와 빠른 진입점을 한 화면에서 제공한다.

### 4.2 레이아웃

1. 상단 앱바
2. 오늘 요약 카드
3. 현재 시간대 출현 생물 섹션
4. 오늘의 일정 섹션
5. 빠른 이동 카드 그리드

### 4.3 상태

1. 초기 로딩: 스켈레톤 카드 3종 표시
2. 부분 로딩: 기존 캐시 유지 후 상단 새로고침 인디케이터 표시
3. 에러: 캐시가 있으면 캐시 유지 + 인라인 배너, 없으면 전체 에러 뷰
4. 빈 일정: "오늘 등록된 일정이 없습니다" 카드 표시

### 4.4 주요 액션

1. 생물 카드 탭: 관련 카탈로그 또는 상세 화면으로 이동
2. 일정 카드 탭: 일정 탭의 선택 날짜 상세로 이동
3. 빠른 이동 카드 탭: 각 탭의 대표 화면으로 이동

## 5. 주민 화면

### 5.1 목록 화면

1. 상단 검색바
2. 필터 칩 행
3. 정렬 버튼
4. 주민 카드 리스트
5. 선택 상태용 하단 액션 시트 진입 버튼은 두지 않고 카드 내부 액션 사용

### 5.2 셀 구성

1. 주민 얼굴 이미지
2. 한글 이름, 영문 이름
3. 종족, 성격
4. 섬 거주 여부 배지
5. 즐겨찾기/거주 상태 토글 액션

### 5.3 상세 화면

1. 상단 히어로 이미지
2. 기본 정보 섹션
3. 상태 섹션
4. 대사/생일/취향 섹션
5. 관련 액션 버튼

### 5.4 상태

1. 검색 결과 없음: 필터 초기화 CTA 노출
2. 저장 실패: 해당 카드 하단에 에러 문구 표시 + 재시도 버튼
3. 섬 주민 10명 초과 시도: 토스트가 아니라 인라인 경고 다이얼로그 사용

## 6. 카탈로그 화면

### 6.1 타입 선택

1. 상단 세그먼트 또는 드롭다운으로 카탈로그 타입 전환
2. 타입 전환 시 각 타입의 마지막 스크롤 위치와 필터 상태 유지

### 6.2 목록 화면

1. 검색바
2. 필터/정렬 진입 버튼
3. 활성 필터 칩
4. 아이템 카드 또는 리스트 셀
5. 무한 스크롤 로더

### 6.3 셀 구성

1. 썸네일
2. 이름
3. 카테고리 또는 보조 메타 정보
4. 보유 상태 체크
5. 변형 수 배지

### 6.4 상세 화면

1. 이미지 캐러셀 또는 대표 이미지
2. 아이템 메타 정보
3. 보유/기증/수량 상태 컨트롤
4. 변형 목록
5. 타입별 확장 섹션

### 6.5 타입별 예외

1. `recipes`: 레시피 태그 필터 별도 섹션 제공
2. `art`: 진품/가품 정보 섹션 제공
3. `photos`: 카테고리 필터 숨김
4. `special_items`: 원본 카탈로그 타입 기반 상태 배지 표시

## 7. 일정 화면

### 7.1 월간 화면

1. 월 이동 헤더
2. 캘린더 그리드
3. 날짜별 점/배지
4. 선택 날짜 요약 패널
5. 플로팅 추가 버튼

### 7.2 일자 상세 화면

1. 날짜 헤더
2. 등록 일정 리스트
3. 완료 체크 토글
4. 수정/삭제 액션

### 7.3 일정 편집 시트

1. 제목 입력
2. 날짜 선택
3. 메모 입력
4. 저장 버튼

### 7.4 상태

1. 빈 날짜: 빈 상태 일러스트 대신 간단 카드 사용
2. 저장 중: 시트 닫지 않고 버튼 로딩
3. 삭제 실패: 스낵바 + 원래 항목 복구
