# iOS App Store 심사 체크리스트

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`
- 목적: 현재 프로젝트를 iPhone 앱으로 제출할 때 심사 리스크를 줄이기 위한 체크리스트

## 1. 기능 완성도

- [ ] 하단 탭과 주요 화면이 모두 실제 기능으로 연결된다
- [ ] 미구현 메뉴/빈 placeholder 섹션이 남아 있지 않다
- [ ] 네트워크 실패 시 빈 화면 대신 오류 안내가 나온다
- [ ] 로딩 상태, 빈 결과 상태, 서버 오류 상태가 분리되어 있다

## 2. 네이티브 앱 기준

- [ ] 단순 웹뷰 포장 앱처럼 보이지 않는다
- [ ] 목록/상세/편집이 iOS 기본 탐색 패턴을 따른다
- [ ] 터치 타깃과 시트/네비게이션 동작이 자연스럽다

## 3. 데이터/저작권

- [ ] Nookipedia 데이터와 이미지 사용 조건을 정리했다
- [ ] 로컬 정적 이미지 자산의 출처와 사용 범위를 정리했다
- [ ] Animal Crossing 관련 명칭/이미지 사용 리스크를 검토했다
- [ ] 필요 시 앱 설명에 비공식 팬 프로젝트 성격을 명시할지 결정했다

## 4. 개인정보/계정

- [ ] 로그인 없음 기준이라면 개인정보 수집 최소화 내용을 정리했다
- [ ] 분석/크래시 SDK를 넣는다면 수집 항목을 문서화했다
- [ ] 로그인 도입 시 계정 삭제 경로 요구사항을 따로 준비했다
- [ ] 개인정보 처리방침 필요 여부를 검토했다

## 5. 네트워크/안정성

- [ ] 모든 API/이미지 URL이 HTTPS를 사용한다
- [ ] 네트워크 불가 상태에서도 앱이 죽지 않는다
- [ ] 첫 실행 시 서버 연결 실패 안내가 있다
- [ ] 재시도 버튼 또는 복구 경로가 있다

## 6. 메타데이터 준비

- [ ] 앱 이름 확정
- [ ] 서브타이틀/설명 초안 작성
- [ ] 키워드 초안 작성
- [ ] 스크린샷 시나리오 정의
- [ ] 지원 URL/문의 URL 준비
- [ ] 필요 시 개인정보 처리방침 URL 준비

## 7. 검수 전 최종 확인

- [ ] 크래시 없는 빌드 확보
- [ ] 테스트 계정이 필요한 앱으로 바뀌면 검수 계정 제공 준비
- [ ] 앱 심사 메모에 프로젝트 특성을 짧게 설명할 수 있다
