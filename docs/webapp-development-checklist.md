# Web App Development Checklist

기준 문서:
- `SRS.md`
- `SAD.md`
- `SDS.md`
- `docs/webapp-development-plan.md`

기준 날짜: 2026-08-24

사용 규칙:
- 작업 시작: `- [ ]`를 `- [~]`로 변경
- 작업 완료: `- [x]`로 변경
- 보류/범위 제외: 항목 끝에 사유 기록

## 1. 범위 고정

- [ ] MVP 포함 화면을 확정했다: `Onboarding`, `Today`, `Catalog`, `Villagers`, `My Island`
- [ ] Post-MVP 화면을 확정했다: `Guide`
- [ ] `frontend/`를 웹앱 메인 구현 위치로 확정했다
- [ ] 기존 `static/` 앱과 신규 웹앱의 역할을 문서로 구분했다

## 2. 앱 셸

- [ ] `App.tsx`가 단일 화면 렌더링에서 앱 라우터 구조로 바뀌었다
- [ ] 기본 경로가 정의됐다: `/onboarding`, `/today`, `/catalog`, `/villagers`, `/my-island`
- [ ] `AppShell`이 라우팅 구조와 연결됐다
- [ ] `BottomNavigation`이 실제 경로 이동과 연결됐다
- [ ] `IslandSidebar`가 실제 섬 데이터와 연결됐다
- [ ] 잘못된 경로 처리 규칙이 정해졌다

## 3. 전역 상태

- [ ] 활성 섬 상태가 전역으로 관리된다
- [ ] 현재 게임 날짜 상태가 전역으로 관리된다
- [ ] 세션/초기 로딩 상태가 전역 또는 루트에서 관리된다
- [ ] 섬 변경 시 관련 화면 데이터가 함께 갱신된다
- [ ] 날짜 변경 시 오늘 화면 데이터가 함께 갱신된다

## 4. 타입과 API 계층

- [ ] 프론트엔드 API 클라이언트 구조가 정리됐다
- [ ] 홈 요약 타입이 정의됐다
- [ ] 섬 타입이 정의됐다
- [ ] 루틴 타입이 정의됐다
- [ ] 카탈로그 아이템/수집 상태 타입이 정의됐다
- [ ] 주민/주민 상태 타입이 정의됐다
- [ ] NPC 방문 기록 타입이 정의됐다
- [ ] API 에러 응답 타입이 정의됐다

## 5. 온보딩

- [ ] 섬 이름 입력이 가능하다
- [ ] 반구 선택이 가능하다
- [ ] 대표 과일 선택이 가능하다
- [ ] 대표 꽃 선택이 가능하다
- [ ] 대표자 이름 입력이 가능하다
- [ ] 대표자 생일 선택이 가능하다
- [ ] 필수값 검증이 동작한다
- [ ] 첫 섬 생성 후 오늘 화면 또는 기본 홈으로 이동한다

## 6. 섬 선택과 관리

- [ ] 섬 목록 조회가 가능하다
- [ ] 활성 섬 전환이 가능하다
- [ ] 섬 생성이 가능하다
- [ ] 섬 수정이 가능하다
- [ ] 섬 삭제 전 영향 범위 경고가 나온다
- [ ] 섬 삭제 확인 문구가 동작한다
- [ ] 대표자 정보 수정이 가능하다

## 7. 오늘 화면

- [ ] 홈 요약 API가 연결됐다
- [ ] 현재 활성 섬 이름이 노출된다
- [ ] 현재 게임 날짜가 노출된다
- [ ] 날짜 변경 UI가 동작한다
- [ ] 시즌/이벤트/생일 정보 영역이 실데이터로 렌더링된다
- [ ] 루틴 진행률이 API 데이터로 계산된다
- [ ] 루틴 완료 토글이 저장된다
- [ ] 현재 가능한 생물 목록이 표시된다
- [ ] 최근 NPC 방문 기록이 표시된다
- [ ] 로딩/빈 상태/에러 상태가 분리되어 있다

## 8. 루틴

- [ ] 루틴 정의 목록 조회가 가능하다
- [ ] 루틴 완료 상태 변경이 가능하다
- [ ] 수량형 루틴 카운트 변경이 가능하다
- [ ] 루틴 추가가 가능하다
- [ ] 루틴 수정이 가능하다
- [ ] 루틴 삭제가 가능하다
- [ ] 루틴 정렬 순서 변경이 가능하다
- [ ] 날짜별 루틴 상태가 분리 저장된다

## 9. 도감/카탈로그

- [ ] 카탈로그 화면이 API 데이터로 렌더링된다
- [ ] 카테고리 전환이 동작한다
- [ ] 검색이 동작한다
- [ ] 필터가 동작한다
- [ ] 정렬이 동작한다
- [ ] 진행률 표시가 실제 수치와 일치한다
- [ ] 아이템 상세 보기 진입이 가능하다
- [ ] 보유 상태 변경이 저장된다
- [ ] 기증 상태 변경이 저장된다
- [ ] 채집 상태 변경이 저장된다
- [ ] 섬별 수집 상태가 분리된다

## 10. 주민

- [ ] 주민 목록 조회가 가능하다
- [ ] 이름 검색이 가능하다
- [ ] 성격 필터가 가능하다
- [ ] 종족 필터가 가능하다
- [ ] 서브타입 필터가 가능하다
- [ ] 주민 상세 보기 진입이 가능하다
- [ ] 현재 주민 상태 변경이 가능하다
- [ ] 위시 주민 상태 변경이 가능하다
- [ ] 캠핑 방문 기록이 가능하다
- [ ] 과거 주민 기록이 가능하다
- [ ] 사진 보유 여부 기록이 가능하다
- [ ] 주민 상태가 섬별로 분리 저장된다

## 11. NPC 방문 기록

- [ ] 최근 7일 기록 조회가 가능하다
- [ ] 방문 기록 추가가 가능하다
- [ ] 방문 기록 수정이 가능하다
- [ ] 방문 기록 삭제가 가능하다
- [ ] 날짜별로 정렬되어 표시된다
- [ ] 섬별로 분리 저장된다

## 12. UI/UX 품질

- [ ] 모바일 레이아웃이 깨지지 않는다
- [ ] 태블릿 이상 레이아웃이 깨지지 않는다
- [ ] 긴 텍스트 처리 규칙이 있다
- [ ] 빈 상태 문구가 있다
- [ ] 에러 상태 문구와 재시도 액션이 있다
- [ ] 버튼/입력/탭 포커스 스타일이 있다
- [ ] 클릭 영역이 충분하다
- [ ] 색상과 대비가 과도하게 약하지 않다

## 13. 데이터 분리와 저장

- [ ] 모든 상태 변경 요청에 활성 섬 기준이 반영된다
- [ ] 다른 섬 데이터가 현재 섬 화면에 섞이지 않는다
- [ ] 새로고침 후 활성 섬 컨텍스트가 유지된다
- [ ] 날짜 변경 후 기록 저장 기준이 일관된다

## 14. 테스트

- [ ] 최소 smoke test 경로가 정리됐다
- [ ] 온보딩 플로우를 수동 검증했다
- [ ] 섬 전환 플로우를 수동 검증했다
- [ ] 오늘 화면 핵심 플로우를 수동 검증했다
- [ ] 도감 상태 변경 플로우를 수동 검증했다
- [ ] 주민 상태 변경 플로우를 수동 검증했다
- [ ] 주요 컴포넌트 렌더링 테스트가 있다
- [ ] 주요 API 상태 처리 테스트가 있다

## 15. 배포 준비

- [ ] 웹앱 빌드가 성공한다
- [ ] 환경 변수 목록이 정리됐다
- [ ] 개발/배포 API 엔드포인트 구분이 정리됐다
- [ ] 웹앱 엔트리 기준이 문서화됐다
- [ ] 배포 전 확인 항목이 별도 문서 또는 체크리스트로 연결된다

## 16. 보류 항목

- [ ] 날씨 시드 기능은 Post-MVP로 분리했다
- [ ] MeteoNook 연동은 Post-MVP로 분리했다
- [ ] 무주식 계산기는 Post-MVP로 분리했다
- [ ] 공략 허브는 Post-MVP로 분리했다
- [ ] variation 단위 수집 관리는 후속 범위로 분리했다
