# Flutter 디자인 시스템

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`

## 1. 목표

1. 게임 톤을 유지하면서 정보 앱으로 읽기 쉬운 UI를 만든다.
2. Flutter 위젯 재사용성을 높인다.
3. iOS와 Android에서 같은 디자인 언어를 유지하되 플랫폼 기본 제스처는 존중한다.

## 2. 디자인 방향

1. 톤: 따뜻하고 밝은 생활 기록 앱
2. 키워드: paper, leaf, wood, museum label
3. 시각적 우선순위: 콘텐츠 이미지 > 상태 배지 > 보조 메타 정보

## 3. 디자인 토큰

### 3.1 Color

1. `primary`: 잎사귀 계열 그린
2. `secondary`: 따뜻한 베이지
3. `accent`: 벨 포인트용 골드
4. `success`: 소프트 그린
5. `warning`: 오렌지
6. `error`: 레드
7. `surface`: 오프화이트
8. `surfaceVariant`: 연한 종이색
9. `outline`: 낮은 채도의 브라운 그레이

### 3.2 Typography

1. 제목용 한글/영문 조합 폰트 1종
2. 본문용 가독성 폰트 1종
3. 숫자 표시가 많은 카운트/가격은 tabular figure 우선

### 3.3 Spacing

1. 기본 단위 `4`
2. 주요 간격: `4, 8, 12, 16, 24, 32`

### 3.4 Radius

1. 카드 `16`
2. 시트 `20`
3. 칩 `999`
4. 입력 필드 `12`

## 4. 핵심 컴포넌트

1. 앱바
   - 대형 타이틀은 홈/탭 루트에서만 사용
2. 카드
   - 홈 요약 카드
   - 주민 카드
   - 카탈로그 아이템 카드
   - 빈 상태 카드
3. 칩
   - 필터 칩
   - 상태 칩
   - 카테고리 칩
4. 버튼
   - Primary
   - Secondary
   - Tonal
   - Destructive
5. 시트
   - 필터 시트
   - 일정 편집 시트

## 5. 목록 패턴

1. 이미지가 중요한 목록은 2열 카드 레이아웃 허용
2. 텍스트 탐색 위주 목록은 1열 리스트 사용
3. 동일 화면에서 카드와 리스트를 혼합하지 않는다.

## 6. 상태 표현 규칙

1. 보유/미보유는 색상 + 아이콘 함께 사용
2. 완료/미완료는 체크 형태로 통일
3. 경고는 배너보다 인라인 카드 우선
4. 로딩은 스피너보다 스켈레톤 우선

## 7. 이미지 정책

1. 썸네일은 고정 비율 유지
2. 로드 실패 시 카테고리별 fallback asset 사용
3. 투명 PNG 배경은 surfaceVariant 위에 배치

## 8. 다크 모드

1. 1차 출시에서는 지원 가능하되 필수 범위는 아니다.
2. 다크 모드를 열 경우 pure black 대신 desaturated dark brown 계열 사용

## 9. 접근성

1. 대비 비율 준수
2. 스크린리더 순서 명시
3. 상태 배지에 텍스트 의미 포함
4. 애니메이션 감소 설정 존중

## 10. 산출물 메모
