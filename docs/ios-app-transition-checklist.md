# iPhone 앱 전환 체크리스트

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`
- 현재 기준: `FastAPI + static SPA + SQLite(app.db) + content.db`
- 목적: 현재 웹/API 프로젝트를 iPhone 앱으로 전환하기 전에 필요한 문서를 순서대로 준비하고, 의사결정 누락 없이 구현에 들어가기 위한 체크리스트

## 2. 현재 웹/API 프로젝트에서 재사용 가능한 부분과 새로 만들어야 할 부분

### 2.1 재사용 가능한 부분

- [ ] FastAPI 백엔드의 읽기 API를 모바일 클라이언트용으로 계속 사용할지 결정
- [ ] 카탈로그/주민/홈/캘린더 데이터 모델을 모바일에서도 동일하게 사용할지 확인
- [ ] `content.db` 기반 조회 구조를 모바일 백엔드의 기준 데이터 소스로 유지할지 확인
- [ ] 한글명/종/성격/이벤트 매핑 JSON을 백엔드 기준 데이터로 재사용할지 확인
- [ ] 음악 로컬 정적 이미지 구조(`static/assets/music`)를 CDN 또는 앱 캐시 구조로 재사용할지 결정
- [ ] 현재 상태 저장 개념(보유/기증/수량/섬 프로필/플레이어/캘린더)을 모바일 도메인 모델로 그대로 가져갈지 검토

### 2.2 새로 만들어야 할 부분

- [ ] iOS 앱 클라이언트 구조 결정
- SwiftUI 우선 여부
- 최소 지원 iOS 버전
- 라우팅/탭 구조
- [ ] 모바일 전용 네트워크 레이어 설계
- API 에러 표준화
- 재시도 정책
- 타임아웃 정책
- [ ] 모바일 전용 상태관리 설계
- 서버 상태 캐시
- 화면 상태
- 오프라인 큐
- [ ] 모바일 전용 상세 화면, 하단 탭, 검색/필터 UX 설계
- [ ] 원격 이미지 캐시 전략 설계
- [ ] 오프라인 저장 범위와 동기화 정책 설계
- [ ] 앱 배포용 설정 체계
- dev/staging/prod
- 번들 ID
- 앱 설정값 주입 방식

## 3. 기존 인증/세션 구조가 iOS 앱에 맞는지

### 3.1 현재 상태 확인

- [ ] 현재 API에 로그인 기능이 없는지 확인
- [ ] 상태 변경 API가 인증 없이 호출 가능한지 확인
- [ ] `app.db`가 단일 사용자 기준인지 확인
- [ ] 상태 테이블에 `user_id` 스코프가 없는지 확인
- [ ] CORS/동일 오리진 전제를 모바일 앱에서도 유지할 수 없는 점을 명시

### 3.2 iOS 전환 시 결정해야 할 것

- [ ] 무인증 단일 사용자 앱으로 갈지, 로그인 지원 앱으로 갈지 결정
- [ ] 로그인 지원 시 인증 방식 결정
- 서버 세션
- JWT + refresh token
- OAuth 기반 소셜 로그인
- [ ] 토큰 저장 위치를 Keychain으로 고정할지 결정
- [ ] 익명 사용자 로컬 사용 후 계정 연동을 지원할지 결정
- [ ] 멀티 디바이스 동기화가 필요한지 결정
- [ ] 로그아웃/토큰 만료/네트워크 실패 UX를 정의

### 3.3 문서 산출물

- [ ] 인증/세션 설계서 초안 작성
- [ ] 사용자 데이터 분리 정책 문서 작성
- [ ] 보안 저장(Keychain) 정책 문서 작성

## 4. 모바일 전용 UX가 필요한 기능

### 4.1 탐색 구조

- [ ] 현재 상단 웹 네비게이션을 iPhone 하단 탭 또는 계층형 네비게이션으로 재설계
- [ ] `홈 / 주민 / 카탈로그 / 일정 / 설정` 정보 구조 초안 작성
- [ ] 현재 브레드크럼/서브메뉴를 모바일에 맞게 단순화

### 4.2 목록과 상세

- [ ] 현재 카드 그리드가 iPhone 폭에서 몇 열로 보여야 하는지 정의
- [ ] 상세 모달을 모바일에서는 풀스크린 push 또는 sheet로 바꿀지 결정
- [ ] 이전/다음 상세 이동을 유지할지, 목록 복귀 중심으로 바꿀지 결정
- [ ] 대량 체크 기능이 모바일에서 너무 무거운지 검토

### 4.3 검색/필터/정렬

- [ ] 검색창 상시 노출 여부 결정
- [ ] 필터/정렬을 bottom sheet로 통합할지 결정
- [ ] 적용된 필터 요약 배지 규칙 정의
- [ ] 빈 결과/로딩/오류 상태 UI 문구 정의

### 4.4 입력/수정 플로우

- [ ] 섬 프로필 수정 화면을 폼 화면으로 분리할지 결정
- [ ] 캘린더 일정 추가/수정 플로우를 iOS date picker 기반으로 재설계
- [ ] 플레이어 추가/삭제/대표 설정 플로우를 터치 UX 기준으로 정리

### 4.5 접근성

- [ ] 최소 터치 영역 `44pt` 준수
- [ ] Dynamic Type 대응 여부 결정
- [ ] VoiceOver 기본 라벨 정책 정의
- [ ] 색상 외 상태 표현 보조 텍스트/아이콘 규칙 정의

## 6. App Store 심사에 걸릴 수 있는 요소 점검

### 6.1 개인정보/계정

- [ ] 로그인 도입 시 계정 삭제 플로우가 필요한지 확인
- [ ] 개인정보 처리방침이 필요한지 확인
- [ ] 수집 데이터 목록을 문서화

### 6.2 외부 콘텐츠/저작권

- [ ] Nookipedia 기반 데이터/이미지 사용이 앱 배포에 적합한지 라이선스 확인
- [ ] 로컬 저장된 이미지 자산의 사용 근거 정리
- [ ] 앱 설명/스크린샷에서 상표 사용 리스크 검토

### 6.3 앱 동작 정책

- [ ] 웹뷰 래핑 수준의 앱이 되지 않도록 네이티브 UX 범위 정의
- [ ] 빈 화면, 플레이스홀더, 미구현 메뉴가 심사 이슈가 되지 않게 제거 범위 결정
- [ ] 네트워크 실패 시 앱이 깨지지 않는지 확인
- [ ] 외부 링크, 문의, 개인정보 페이지 연결 구조 정의
