# Flutter 위젯 테스트 전략

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`

## 1. 목표

1. 핵심 화면의 상태별 UI를 자동 검증한다.
2. Riverpod provider와 화면 상호작용을 안정적으로 테스트한다.
3. 회귀가 잦은 목록/상세/편집 플로우를 위젯 테스트 범위에 포함한다.

## 2. 우선 대상

1. 홈 요약 화면
2. 주민 목록 화면
3. 카탈로그 목록/상세 화면
4. 일정 추가/체크/삭제 플로우
5. 공통 에러/빈 상태 컴포넌트

## 3. 케이스 분류

1. 로딩 상태 렌더링
2. 정상 데이터 렌더링
3. 빈 상태 렌더링
4. 에러 상태 렌더링
5. 버튼/토글 인터랙션
6. optimistic update와 rollback

## 4. 테스트 구성 원칙

1. 네트워크는 fake repository 또는 mock client로 대체
2. provider override로 상태를 주입
3. golden test는 핵심 카드/셀 중심으로 제한 운영
4. locale은 한국어 기준 스냅샷을 우선 사용

## 5. 제외 범위

1. OS 권한 다이얼로그
2. 실제 이미지 다운로드 검증
3. 스토어 제출 메타데이터
