# iOS 환경/배포 계획

- 작성일: 2026-03-12
- 대상 프로젝트: `nookipedia-api`
- 목적: iPhone 앱의 환경 분리와 릴리즈 운영 기준을 정의한다.

## 1. 환경 분리

권장 환경:

1. `dev`
2. `staging`
3. `prod`

각 환경 차이:

1. API base URL
2. 앱 표시 이름 suffix
3. 로그/분석 전송 여부
4. 디버그 메뉴 노출 여부

## 2. 설정값

앱에서 환경별로 주입할 항목:

1. `API_BASE_URL`
2. `APP_ENV`
3. `ENABLE_DEBUG_MENU`
4. `ANALYTICS_ENABLED`

## 3. 빌드 채널

1. 로컬 개발 빌드
2. 내부 테스트 빌드
3. TestFlight 빌드
4. App Store 배포 빌드

## 4. 릴리즈 단계

1. 개발 환경 수동 확인
2. 스테이징 연결 확인
3. QA 시나리오 수행
4. TestFlight 배포
5. 내부 검토
6. App Store 제출

## 5. 출시 게이트

- [ ] 핵심 QA 시나리오 통과
- [ ] 서버 base URL 최종 확인
- [ ] 크래시 없는 빌드 확보
- [ ] App Store 메타데이터 준비
- [ ] 심사 리스크 항목 1차 정리

## 6. 권장 운영 규칙

1. 스테이징과 프로덕션 URL을 앱 내에서 혼동하지 않게 이름을 분리한다.
2. 디버그 메뉴는 프로덕션에서 숨긴다.
3. TestFlight 노트에 변경 기능과 테스트 포인트를 짧게 적는다.
